# 界面走查：先修窄屏操作，再统一视觉

## 结论

当前界面已经形成完整的资源处理工作台，但还没有落实 `DESIGN.md` 的主要视觉约束。最明显的差异是蓝灰底色、偏小的文字、统一的方圆按钮，以及白色侧栏加多层圆角面板。建议保留现有功能、路由、密集桌面图片墙和快速审阅，先统一全局样式；不要逐页增加装饰，也不要把工作台改成商品宣传页。

优先修正两项使用问题：手机图片点击区域过小，以及设置草稿离页时没有保护。然后再调整导航、字体、按钮和面板层级。

## 优先处理的具体问题

### P1：手机图片按钮不足 44px，难以准确选择

**证据：** `web/app/assets/main.css:290–299` 将本地图片墙下限固定为十列，且图片按钮覆盖了全局的最小高度。实际 CSS 视口为 `375 × 813` 时，图片按钮约为 `31.7 × 31.7px`；417px 时约为 `35.9 × 35.9px`。这不符合 `DESIGN.md:527–530` 的 44px 触控下限。

同类问题还存在于云端操作：`web/src/XiaomiPanel.vue:455` 的图片墙回收按钮为 32px，`:464` 的列表回收按钮宽度为 28px，属于源码确认，未在已登录云相册实看。

**建议：** 桌面保留现有密集模式；手机按至少 44px 的实际按钮尺寸计算列数。云端回收可以保留小图标，但实际点击区域扩到 44px，并避免覆盖整张缩略图。

### P1：离开设置页面会丢掉未保存草稿

**证据：** `web/src/SettingsPanel.vue:11–16、28–30、64、97` 记录了 `dirty` 并显示提示，但没有离页确认；`:57` 卸载时清除敏感输入。`web/app/pages/[...path].vue:203–206` 切换到其他主导航会卸载设置组件。该项由调用关系确认，没有输入或保存配置来复现。

**影响：** 用户填写代理、API 信息或修改规则后，点击其他主导航再返回，会失去尚未保存的输入；“有未保存的更改”本身不能阻止这种情况。

**建议：** 仅在草稿变动时，为主导航离页及刷新提供“继续编辑 / 放弃更改”的保护。不自动保存密码或连接配置，也不要取消现有卸载清理敏感输入的行为。

### P2：全局颜色和导航没有采用设计文档的基础系统

**证据：** `web/app/assets/main.css:7–20` 实际使用 `#17263b`、`#eef2f6`、`#145bc7`，对应文档要求的是 `#1d1d1f`、`#f5f5f7`、`#0066cc`。`:79–96` 使用白色侧栏和普通页面标题，没有文档的 44px 黑色全局导航、52px 磨砂次导航。

**建议：** 先修改共享 token，再统一外壳。保留八个功能入口和既有地址，桌面采用黑色紧凑导航与浅色次导航；将页面名称、筛选与主要动作集中在次导航，避免正文内重复一层标题和工具条。

### P2：手机导航把八个入口放在一条横向滚动栏中

**证据：** `web/app/assets/main.css:173–179、320`。375px 页面中，导航可见宽约 338px，内部内容宽约 754px；后半段入口需要横向滚动才能发现。700–960px 又切换为只有图标的侧栏，与文档 833px 附近折叠导航的方式不同。

**建议：** 窄屏使用明确的菜单入口，展开后显示全部功能名称；当前页面名称与主要动作保持可见。不要通过继续缩小导航文字、隐藏更多名称或让按钮文字换行解决。

### P2：正文、标签和操作文字整体偏小

**证据：** `web/app/assets/main.css:23、47、60、67、109–115、125、198`。根字号为 15px，表单标签、次要文字大量为 12–14px，手机部分说明降到 11px；字体栈也没有优先采用文档指定的系统字体。工作流名称等另有 500 字重，见 `:220、234`。

**建议：** 正文和主要表单输入以文档的 17px / 400 / 1.47 为基准，必要说明采用 14px，12px 留给真正的辅助元数据。标题采用 600。系统字体优先，保留中文回退，不为此次统一额外下载字体。日志代码区和密集数据列按用途单独处理，不能机械地把所有内容都放大成正文。

### P2：按钮、圆角、搜索和阴影没有遵循文档的用途区分

**证据：** `web/app/assets/main.css:30、60–66、117、140、278、283–285`。主次按钮均为 8px 圆角，按压缩放为 `.97`，搜索框也是 8px；面板为 16px。图片分段选项和浮动按钮有阴影。另见 `web/src/ImageReviewDialog.vue:333–335、354` 与 `web/src/ImageDedupPanel.vue:376`。

**建议：** 蓝色主动作与搜索采用胶囊；紧凑工具按钮保持 8px，真正的功能容器采用 18px。按压反馈统一到文档的 `.95`，继续尊重 reduced-motion。移除控件阴影，使用表面色、细线与磨砂区分层级；不要给每个小分组再加卡片。

### P2：未配置首页先展示完整流程，而不是先完成连接

**证据：** 实看首页，未连接账号时仍先显示八个处理步骤，连接 Telegram 的按钮位于其后；`web/app/pages/[...path].vue:190–196` 决定了这个顺序。空统计和空最近记录又延长了页面。

**建议：** 未配置时优先显示连接动作；配置完成后再以当前任务和队列为主体。完整步骤作为辅助展开区域，保留可查看每一步状态的能力。已完成配置的工作台不要变成大型介绍页。

### P2：小米相册工具条过多动作同层并列

**证据：** `web/src/XiaomiPanel.vue:349–363` 同区放置图片墙开关、刷新、按文件名回收、设备上传、本地目录上传及上传记录；`:429` 通过 `flex-wrap` 排列。此项来自已登录界面的模板，未完成该状态的实看。

**建议：** 保留一个主要“上传”入口，将设备来源和服务器目录来源放入其选择；刷新和视图属于浏览工具，回收放进管理区，上传记录归到上传区。优先重新分组，不增加说明段落或把按钮挤成两行。

### P2：部分弹窗没有可访问名称，图片标签页缺少完整键盘行为

**证据：** 整理预览和还原确认实看时，辅助功能树只呈现无名称的容器。源码中 `web/src/FilesPanel.vue:76`、`web/src/ImagesPanel.vue:491、502`、`web/src/XiaomiPanel.vue:408`、`web/src/XiaomiBatchUpload.vue:244` 以及主页面 `:210` 的 dialog 均未关联标题。相较之下，快速审阅已经正确设置 `aria-labelledby`。

`web/src/ImagesPanel.vue:402–406` 声明了 `tablist/tab`，但没有相应的方向键切换、焦点管理或面板关联。

**建议：** 复用快速审阅现有的标题关联方式；图片视图若作为标签页，就补齐键盘与面板关系，否则使用语义正确的导航链接。不要只添加 ARIA 角色而保留不匹配的操作方式。

### P2：本地匹配状态在视觉上依赖红绿黄颜色

**证据：** `web/src/XiaomiLocalIndicator.vue:6–18` 只有色点/色条，虽然有 `aria-label` 和鼠标提示，但普通视觉用户需要对照 `XiaomiLocalBinding.vue:87–89` 的图例，手机没有稳定的悬停提示。

**建议：** 在列表提供简短状态词，在图片墙提供可区分的图形并允许查看完整状态。蓝色仍是唯一品牌交互色；错误、危险操作、匹配状态作为语义色另行约定。`DESIGN.md` 本来没有定义完整错误状态，不应为了单色外观把危险确认也改成普通蓝色动作。

## 各页面应保留什么、调整什么

- **登录：** 保留“拾存”的收纳盒标识与简短用途说明。先对齐中性色、系统字体及胶囊主动作，不添加宣传语或大图背景。
- **工作流：** 保留状态步骤和可恢复的队列操作。先连接、后任务；不要让所有流程卡片在空状态与运行状态中争夺同样的视觉权重。
- **下载记录与详情：** 保留文件名、状态、速度和分卷信息。减少外框层数，优先保证文件名可读，详情沿用已有的渐进展开方式。
- **路径打平：** 保留执行前的源路径到目标路径对照及取消入口。预览说明只保留当前移动/回收范围和恢复条件，不让通用说明比变更清单更醒目。
- **本地快筛：** 保留日期分组、桌面密集视图、搜索、四个图片视图。手机先满足点击尺寸；重复图继续双图对照，不只用一个“重复”标签代替证据。
- **快速审阅：** 这是当前最接近“内容优先”的界面。保留大图、计数、可见翻图按钮、缩略队列、明确的回收标记与撤销入口，主要调整公共样式，不推翻布局。
- **回收站：** 保留 15 天保留期、原路径、冲突不覆盖及失败保留信息。把安全条件放在确认动作附近，图片区域优先展示可识别的内容。
- **图片去重：** 保留分组导航、参考图、尺寸/大小/相似度和明确回收清单。目录设置属于准备区，扫描结果属于主区；不要再套一层同样显眼的面板。
- **小米云：** 保留相册入口、日期定位、上传历史、绑定目录和联动回收确认。优先整理工具条，并补齐小按钮点击区域与状态表达。
- **日志：** 保留等宽正文、手动刷新、自动更新和下载。日志字号可以独立于正文，但不要继续压小到不便排错；不添加装饰性深色控制台效果。
- **设置：** 保留分类、可见字段标签及敏感值不回显。先加草稿离页保护，再统一字号和布局；复杂选项的条件与后果继续贴近对应开关。

## 推荐采用的统一方向

### 基础 token

颜色直接采用文档已有六项：Action Blue `#0066cc`、Ink `#1d1d1f`、White `#ffffff`、Parchment `#f5f5f7`、Hairline `#e0e0e0`、Black `#000000`。深色表面文字链接另用文档的 `#2997ff`，不用于浅色页面。

字体优先 `system-ui, -apple-system, BlinkMacSystemFont`，补充中文回退；展示标题 600，正文 400，正文 17px、说明 14px。功能内容左对齐，图片按网格对齐，只有独立空状态和大图审阅使用居中构图。

```text
桌面
┌ 黑色全局导航：拾存 / 工作流 / 图片处理 / 云相册 / 日志与设置 ┐
├ 浅色次导航：当前页面          筛选 / 当前状态 / 主要动作      ┤
│ 任务列表，或占据主体宽度的图片墙                            │
│ 需要时才出现的设置、详情与确认区域                          │
└───────────────────────────────────────────────────────────┘

手机
┌ 菜单 / 拾存                                  账号 ┐
├ 当前页面                               主要动作   ┤
│ 搜索或筛选                                        │
│ 可准确点击的图片 / 文件列表                        │
└ 当前选择与确认动作，避开底部安全区域                ┘
```

对照 brief 后，排除三种不适合本项目的套用：每页放 56px 宣传标题、给任务列表加 80px 区块留白、为了明暗交替强行加入黑色图片分区。文档的摄影优先原则，在这里应体现为用户自己的图片占据主体，而不是另配装饰照片。导航、字体、颜色、按钮和表面规范则应统一落实。
