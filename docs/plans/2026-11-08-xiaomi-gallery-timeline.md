# 小米相册日期索引与懒加载

## 目标与约束

- 图片墙先读取官方日期索引，显示年月导航和完整日期分组，再按可见日期请求照片；每页 30 项，最多同时请求两个日期。
- 保留现有虚拟行渲染与普通列表分页，不复制官方客户端源码，也不引入依赖。
- 缩略图增加有容量和时效上限的内存内容缓存、请求合并和私有条件缓存响应。
- 按相册保留已加载内容和滚动位置；刷新、上传、回收、切换账号时处理失效。
- 不改变上传、原图、本地回收和云端安全确认的契约，不部署远端运行容器。

## 实现顺序

- [x] 后端：接入 prepare/timeline 和按日分页，校验远端日期与数量；保留旧媒体 API。
- [x] 后端：缩略图内容 LRU、过期、并发合并，断开账号与回收失效；ETag 与 private/no-cache。
- [x] 前端：日期占位虚拟行与跳转，按日两并发加载、错误重试、年月时间线。
- [x] 前端：相册视图缓存、滚动恢复，以及刷新/上传/回收失效。
- [x] 自查旧调用方，执行聚焦断言、构建与隔离的界面检查。
- 发布收尾：按仓库规则提交推送，核对 Actions 和 GHCR 镜像标签及 revision；最终提交号和发布结果随交付消息记录。

## 验收与失败处理

官方客户端 4.0.1.328 的只读代码显示：prepare 后取 dayCount，按 startDate=endDate 请求 galleries，每页 30 项、两个在途请求。本项目沿用这些接口与调度上限，同时保留更节制的虚拟行 DOM。

索引未准备好时提示重试，不静默退回整册扫描；日期加载错误就地重试，不无限重发。缓存仅保存本次账号数据且有上限，不写入磁盘；缩略图每次浏览器复用前仍需服务端鉴权。普通列表不依赖日期索引。
