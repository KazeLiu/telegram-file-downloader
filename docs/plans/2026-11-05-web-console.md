# 网页配置与资源处理工作台

## 目标与验收

- 管理页完成管理员密码初始化、TG API / 代理配置、手机号 / 验证码 / 2FA 登录、选群和重新登录。
- Compose 只需调整下载目录；命名数据卷保存账号会话、设置、管理密码和任务记录，正常重建不丢失。
- 首次仅收集启动后的新消息，保留原有进度与断线补下载逻辑。现有 CLI 和配置文件入口继续可用。
- 可设置视频 / 图片 / ZIP、RAR 下载；视频选择最高可用清晰度。
- 压缩包尝试固定密码；完整解压成功后才能按开关删除原包。失败、缺卷或危险路径保留原包。
- 群内原消息下更新同一条回执，显示下载进度、速度、剩余时间、解压 / 清理结果；可标记已读。
- 页面展示实时任务和可分页的历史记录，包括时间、大小、速度、进度、结果。

## 实施边界

- 不替换 Telegram 协议库，不复制账号会话，不查看当前用户的 .env 密钥。
- 不停止当前控制台实例。界面检查使用独立数据目录，不连接 TG、不下载群文件、不删除现有数据。
- 不新增或运行自动化测试。用户已允许本地服务 / 浏览器的页面与交互检查。
- 本轮不增加云上传、视频转码或公网部署。

## 模块与顺序

1. 持久层：独立工作台数据库，管理密码哈希、设置、任务元数据、回执关联；保留原进度数据库。
2. 资源处理：分类与清晰度选择、进度更新、7-Zip 解压、安全路径检查、成功后删除、群内回执。
3. 网页运行时：单个异步控制器管理登录与监听；会话失效显示重新登录入口，不静默注销 / 删除会话。
4. API：管理员会话保护、同源写请求、配置脱敏、登录与选群、运行状态、下载历史。
5. 前端：Vue 3 + TypeScript + SCSS；概览、历史、设置与登录向导；所有状态按具名 xxxModel 聚合。
6. 部署：增加网页 Compose、前端多阶段构建、7-Zip 运行时与迁移文档，保留现有命令行部署文件。
7. 验证：依赖安装 / 构建、源码差异检查、独立页面数据下的桌面与窄屏交互检查。真实 TG / 解压验证由用户后续执行。

## 设计方向

- 使用用户指定的 anthropics/frontend-design 与 getdesign Apple 规范。
- 冷白、浅灰与功能性蓝色；系统字体、清晰数字、充足留白；用列表和分组表达任务，不堆砌同质卡片。
- 左侧三项导航：概览、下载记录、设置。主要区域优先展示正在进行的任务；无数据时给出真实的连接入口。
- 设置按 Telegram、下载规则、解压与回执、安全分组，密码只接受新值、不回传明文。
- 小屏收拢侧栏；键盘焦点、错误反馈、减少动态效果均保留。

## 状态与恢复

- 运行设置持久保存；连接参数变化在当前任务结束后应用，不主动中断用户下载。
- 下载、解压和删除分别记状态；原包删除后依靠任务完成记录防止误判为未下载。
- 解压不执行任何包内程序；禁止外部路径与符号链接，先在专用临时目录完成，再发布到独立输出目录。
- 配置和会话位于 /data；删除 Docker 数据卷才会清除它们，普通 restart / recreate 不会。
- 管理页面默认仅供本地 / Tailscale 使用，不向公网暴露。页面初始化管理密码后，所有账号与设置 API 需要认证。
