# 云端、本地联动回收与到期永久清理

## 目标与范围

- 仅在本项目页面回收小米云文件时联动，不监听手机或官方网页的删除。
- 单张回收及按文件名批量回收均先预览绑定目录内的本地文件；云端确认成功后再回收本地。
- 仅自动处理唯一的同名同大小文件，执行前重新核对文件版本。重复、缺失、不匹配及不可访问分别提示。
- 沿用应用回收站与原路径还原；绑定目录之外的文件不参与。
- 应用回收站保留 15 天；静置到期后由 Docker 自动永久清理，不使用 Windows 回收站或宿主机工具。
- 只发布现有 Linux Docker 镜像，不增加 Windows 原生服务。

## 实现顺序

1. 扩展本地目录索引保存相对路径和文件版本；旧目录缓存重建一次，不更改实际文件。
2. 接入回收预览、云端优先的执行及本地失败重试。复用服务器已读取的云端元数据，不为删除再次遍历云端相册。
3. 单张及批量界面展示预览和分项结果；回收站支持选择绑定目录，还原不覆盖。
4. 服务启动及每小时检查已登记目录的回收站，每批最多清理 100 项。以回收时间和文件最后修改时间中的较晚者计算 15 天；列表查看不重置计时，重新回收生成新记录。
5. 更新部署说明，补充最小自动化检查源码；按项目规则构建、提交推送 master 并确认镜像发布。

## 失败与恢复

- 云端失败不移动本地；云端成功、本地失败保留持久记录，可单独重试本地。
- 本地文件变化或绑定变化要求重新确认；只读挂载明确报错。
- 每个目录使用自身挂载内的 `.tg-trash`，不跨盘硬链接。
- 到期清理和网页还原共用操作锁。删除前先保存清理意图，删除后提交状态；中断后核对文件是否存在，避免重复删除或重新回收用户后来放回的文件。
- 只删除已登记回收站内、已到期且大小未变化的普通文件，不扫描或清理其他目录。清理失败保留文件并显示异常，原有已满 15 天的回收文件也按同一规则处理。

## 验证与交付

- 阅读调用关系和差异；最小检查覆盖云端失败、本地变化、重复文件、还原冲突和 15 天边界。
- 前端沿用 `npm run build`，后端进行语法构建。不使用真实账号执行删除。
- 不运行自动化测试或真实文件清理；目标机器上的实际自动清理行为由部署者确认。
- 发布遵循根目录 AGENTS.md：构建后提交推送 origin/master，等待镜像流水线并核对 latest、sha 标签。
