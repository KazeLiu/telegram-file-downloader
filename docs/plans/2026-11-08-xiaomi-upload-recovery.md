# 小米上传连接恢复与日志降噪

## 依据与边界

- 用户提供的 2026-11-08 日志中，1196 张批次在处理约 1040 张时发生一次存储节点 `ConnectError → EndOfStream → SSLEOFError(errno=8)`，未收到 HTTP 响应。批次最终确认 1042 张、失败 1 张、未上传 153 张。该证据不能把故障定为限流，也不能从 5.061 秒耗时推断请求体已发送或连接池故障。
- 本机官方 Xiaomi Cloud 4.0.1.328 的 `preload-gallery.js` 使用 `upload_block_chunk?chunk_pos=0` 重传同一分片，最多尝试 3 次。只借鉴可重放分片的有界重试；本项目不对创建记录、最终提交、删除等写请求添加通用重试。
- 保留三文件并发、账号级写锁、失败后停止新调度、在途文件收尾和回收前重新核对。未重启运行容器，不重传、不回收用户真实照片。

## 修改范围

- [x] 存储分片仅对连接失败／连接超时有限重试，最多总共 3 次，等待 1 秒、2 秒；证书错误、HTTP 429／账号拒绝／业务失败不重试。重试使用同一分片字节和上传参数，不重建云端记录。
- [x] 结束或停止的批次增加显式重试入口，只把失败／等待项重新排队；保持已确认、已回收、保留及未确认上传记录不重传。原文件变化检查继续生效。
- [x] Docker 输出 INFO 及以上批次摘要；逐文件成功、日期、回收／还原细节保存在有界 DEBUG 文件日志中。只给指定业务 logger 开启 DEBUG，不开启 HTTP 客户端调试日志。
- [x] 同步使用指南与相关断言，检查构建和隔离页面，不进行真实云端联调。
