# 分组展示与后台工作流

## 目标与范围

- 分组入口使用正常尺寸的开关，保留文件名／相似度选择与现有路由。
- 每组完整展开，移除四张截断及展开／收起交互，继续使用虚拟图片墙。
- 整组回收按钮放在组名左侧，沿用原确认、版本检查与回收规则。
- 相似分组由服务启动、下载、解压或整理后的索引完成自动调度，页面只读结果；结果持久化，未变化时直接复用。
- 工作流显示本批相似分组进度及失败；不依赖小米云，不改变已存图片检查的开关。

## 实现与检查

- `image_groups.py` 管理单后台任务、缓存及批次进度；索引或批次再次变动时合并请求，未完成结果不替换缓存。
- `image_library.py` 在索引结束后唤醒分组；`web.py` 负责生命周期和现有批次回调连接。
- `ImagesPanel.vue` 仅轮询状态，分组更新提示用户刷新，不自动替换正在浏览或选择的照片墙。
- `WorkflowSteps.vue` 和任务类型同步新步骤，旧记录与仅解压任务保持可读。
- 阅读调用链和差异；按项目发布规则构建前端及 Python wheel、提交推送并确认镜像发布。不新增或运行测试，不启动应用或浏览器，不操作真实图片。

## 失败与保留

单图失败保留原文件并列入未分组，任务显示错误；新计算未完成时继续提供已缓存的有效版本。首次升级准备仍需要后台处理时间。分组本身不移动、修改或回收文件，只有用户确认的回收才执行文件操作。
