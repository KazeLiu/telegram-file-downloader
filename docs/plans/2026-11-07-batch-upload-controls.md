# 批量上传暂停、停止与完成后回收

## 目标与约束

- 上传过程中可以暂停、继续和停止；控制在文件边界生效，不中断正在提交到小米云的文件。
- 暂停保留当前批次，停止不再上传剩余文件，但仍核对已取得回执的文件。
- 完成或停止后，询问是否把云端已确认的本地图片移入项目回收站；保留 15 天，云端照片不删除。
- 复用现有云端回执、文件版本、修订号和回收确认流程。视频、未上传、失败及未确认的本地文件不移动。
- 暂停仍占用本批次的云端写锁，继续或停止后才结束该批次；刷新网页保留服务端暂停状态，重启服务仍沿用原有的批次清除规则。

## 实现与验收

- [x] `xiaomi_batch.py`：文件边界的暂停门闩、控制状态、停止后的核对及终态结果。
- [x] `web.py`：校验批次身份和动作的控制入口，允许已停止批次重新核对和回收。
- [x] `XiaomiBatchUpload.vue`：操作按钮、准确的等待提示、后台完成通知及每批次一次的回收询问。
- [x] 文档、隔离检查源码、Python 语法检查、前端类型检查和构建。
- [x] 通过 Chrome 插件核对模拟上传界面，不使用真实账号上传或回收。

发布遵循项目的提交、推送和 GHCR 标签核对流程。

## 已取得的证据

- Python `compileall` 与前端 `npm run build`（类型检查及静态构建）成功。
- 模拟界面显示暂停后处理 1/3，继续后停止于 2/3；只向用户询问已确认的 2 张，未上传项保留。
- 选择保留后重新打开不重复询问；手动确认后展示模拟回收结果，不再追加确认。
- 关闭窗口后，正常完成的另一批 1/1 自动重新打开询问；390px 窄屏没有横向溢出。

## 验证边界

默认不执行测试用例。保留针对暂停、继续、停止和云端核对的隔离检查源码；界面采用模拟接口，未执行实际小米云上传链路。真实小米云上传的端到端行为由用户更新容器后确认。
