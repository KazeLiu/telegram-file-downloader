# 节奏播放

## 目标与验收

在独立分支 `codex/rhythm-playback` 增加菜单页 `/#/playback`。进入后选择或新建播放列表，勾选图库，选择仅图片、仅视频或混合。播放列表及喜欢收藏保存在当前浏览器，媒体仍从已授权的本地目录读取。

## 设计与范围

- 沿用 `DESIGN.md` 的浅粉页面、深玫瑰动作、系统字体；选择界面以列表和表单为主，播放区使用中性黑底，原图不裁切、不染色。
- 图库使用下载目录和小米相册已绑定的本地目录，含子目录；不直接请求小米云端原片。不增加任意路径读取接口。
- 图片支持点击下一张、前后按钮、方向键、手机横向滑动、自动播放开关和间隔、缩放还原、全屏、喜欢收藏；视频使用原生控制，播完切换。
- 支持顺序/随机、循环、总时长、慢速/快速/休息阶段、可选节拍器和中性语音提示。暂停保留当前图片倒计时和视频位置；隐藏页面自动暂停，离开页面停止媒体和声音。
- 不搬动文件、不修改现有索引/上传/回收契约，不加入露骨指令或外部媒体。

## 实施顺序

1. `playback.py` 与 `web.py`：已注册图库清单、只读媒体队列、校验目录边界/版本的原文件接口。复用现有路径保护、目录遍历和 FileResponse 的范围请求。
2. `playback.ts` 与 `PlaybackPanel.vue`：播放列表本机保存、图库勾选、媒体过滤、播放器及节奏状态，明确空列表、目录失效、不支持格式和播放受阻的恢复操作。
3. 主页面接菜单及路由，使用组件局部样式，与已发布的私人画廊界面整合；补充使用说明。
4. 阅读完整新增模块和相邻调用、核对差异；执行前端构建和 Python 语法检查。不新增或运行测试，不启动应用或浏览器。按用户的合并发布授权同步 `origin/master`、提交并推送，确认镜像流程及 `latest` / `sha-<完整提交号>` 标签，不更新远端容器。

## 失败与恢复

- 已删除/变化的文件不继续读取，刷新队列后重选；读取失败显示原因和下一项/重试按钮，不静默跳过。
- 不支持的编解码由播放器明确提示；本次不引入转码依赖。
- 本机保存失败保留当前内存中的编辑并提示；损坏的本机数据不自动覆盖。

## 交付证据

记录构建和语法检查的实际结果。真实视频解码、自动播放权限、手机手势、声音和全屏效果由用户在运行环境验收。

## 实施结果

- 独立页面、播放列表、图库多选和媒体类型筛选已接入；播放器包含上述手动/自动操作、喜欢收藏及「仅播放喜欢」筛选。
- `npm run build`（含 Nuxt 类型检查和静态生成）通过。构建提示当前 Node 22.19.0 低于支持版本，并保留 Nitro `cache-driver.mjs` 外部依赖解析警告；未因此中断构建。
- 两个新增/修改的 Python 模块通过 AST 语法检查，`git diff --check` 通过。没有新增或运行测试，没有启动应用/浏览器进行功能或视觉验收。
- `codex/rhythm-playback` 已同步私人画廊界面的主线提交；图片整理工作树没有主线之外的独立提交。用户已授权将播放器一并提交并推送主线，发布结果以 GitHub Actions 为准。
