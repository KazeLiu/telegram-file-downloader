# 图片管理与可恢复清理

## 目标
- 自动、手动整理中的 PSD/TXT 改为移入应用回收站，PDF 保留。已执行的旧删除记录保持原义。
- 图片管理只索引下载根目录的常见栅格图片，分页缩略图、查看大图、单张/本页多选移入回收站；没有复制、剪切、改名。
- 本地筛选疑似未上色图片，保守/宽松两档，默认不选中，不自动清理；说明黑白成稿可能入选。
- Docker 下载挂载内持久保存回收文件与还原记录，重启可还原，不提供永久清空功能。

## 实现顺序
1. storage.py：复用现有路径限制，建立同挂载的回收站及持久操作记录；整理执行按稳定操作 ID 回收，重试不重复移动。隐藏内部目录。
2. image_library.py：SQLite 图片索引、增量后台扫描、受限缩略图与本地图片特征分析。只有变化的文件重新解码，分页查询不读取全部图片。
3. web.py：沿用管理认证，增加索引、缩略图/原图、回收、还原 API。变更文件前检查版本与整理互斥，不覆盖还原目标。
4. Vue 图片管理：沿用当前 Apple 风格、系统字体、蓝色主操作、灰白画布；图片是主体，候选筛选与回收操作放同一工具栏；回收站提供还原。
5. 更新整理文案、历史中的新回收计数、操作文档与依赖说明，推送并跟进镜像发布。

## 验证与边界
- 遵循用户约定，不新增或运行自动化测试。不读取真实账号配置，不操作真实图片或清理真实文件。
- Python 语法检查、前端构建、差异与调用关系检查；已有授权下仅用独立数据和样例图片检查页面。
- 真实图片的候选准确度、大目录实际耗时、回收/还原与中断恢复留给用户现场确认，不宣称已实测。
- 回收占用下载盘空间，不自动过期删除；文件系统需支持原整理已要求的硬链接。同名还原报错，不覆盖。
