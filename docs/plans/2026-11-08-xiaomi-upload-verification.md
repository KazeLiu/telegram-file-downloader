# 上传后与本地回收前的定向核对

## 目标

上传结束后优先核对小米提交接口返回的媒体记录，不再默认从目标相册第一页扫描。回收本地图片前仍重新读取云端数据，按服务端时间限定日期范围，并保留 ID、SHA-1、大小、目标相册和本地文件版本检查。

## 实现边界

- `xiaomi_cloud.py` 保留去重和最终提交响应中的必要字段；浏览器单文件上传响应不变。按日期分页增加结束日期，原有普通分页和按日调用保持兼容。
- `xiaomi_batch.py` 初次核对使用完整回执；需补查或重新核对时，合并相邻日期窗口。时间窗口使用云端时间的 UTC 日期前后各一天，覆盖时区跨日，不使用文件名猜日期。缺少服务端时间才明确显示整册扫描。定向未匹配时保留本地文件，允许稍后重新核对。
- UI 展示核对数量、日期范围、页数与本地回收进度；长请求期间继续读取状态，避免满进度条停留且没有说明。
- 三文件并行上传、暂停/停止、云端写锁、本地回收站 15 天规则保持不变；不增加依赖、不部署远端运行容器。

## 验收

三张同日旧照片有完整回执时，上传后的额外相册查询为零；回收前只读取覆盖该日期的合并窗口。查不到或字段不一致的照片不回收；缺少日期时显示整册核对及页数，不隐藏退化路径。停止不跳过已上传文件的必要核对。真实账号未联调时在交付中说明。

## 实施证据

- 36 项小米相关检查通过，包括三张完整回执零相册查询、三张旧照片一次日期窗口查询、去重记录沿用云端日期、未匹配/变更/网络失败保留、核对错误恢复，以及三并发暂停/停止回归。
- Python 变更文件编译通过；`npm run build` 完成类型检查和静态构建。
- 隔离模拟账号检查了回收询问、长请求中的日期范围和页数、完成后的逐项状态，以及缺少日期时的整册扫描提示；一个 9 秒模拟回收请求期间收到 9 次状态读取，确认轮询未被按钮忙状态阻断。该时长是界面模拟，不是小米实测耗时。
- 界面无浏览器错误或警告，截图位于忽略目录 `.preview/upload-verification-progress.png`。未新增真实云端照片，也未移动用户本地文件；真实小米账号的性能仍需部署后确认。
